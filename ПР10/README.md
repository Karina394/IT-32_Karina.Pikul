# ПР10. Форми, Server Actions, валідація та useActionState

## Варіант 2. Реєстрація на подію

Розроблено форму реєстрації учасника на навчальний захід.

Форма містить чотири поля:
- Ім'я учасника.
- Email.
- Тип події: Лекція, Майстер-клас, Хакатон.
- Причина участі.

Для перевірки введених даних використано бібліотеку Zod та Server Action. Стан форми контролюється за допомогою useActionState.

Після успішної перевірки відображається повідомлення: «Реєстраційні дані перевірено!».

## Контрольні запитання

**1. Для чого використовується атрибут name у полях HTML-форми?**

Атрибут name визначає назву поля, за якою його значення можна отримати з об'єкта FormData.

**2. Яку роль виконує директива «use server»?**

Вона позначає функцію як серверну. Така функція виконується на сервері та може використовуватися для обробки даних форми.

**3. Чому серверна функція з useActionState має два аргументи?**

Перший аргумент — попередній стан форми (prevState), другий — дані форми (formData).

**4. Що містить об'єкт FormData?**

Він містить значення полів форми, які мають атрибут name.

**5. Для чого потрібен schema.safeParse()?**

Він перевіряє дані відповідно до схеми Zod і повертає результат перевірки: успіх або помилки, не перериваючи виконання винятком через неправильні дані.

**6. Чому валідацію не можна виконувати лише в браузері?**

Тому що перевірку в браузері можна обійти або змінити дані перед надсиланням. Серверна перевірка забезпечує додаткову надійність.

**7. Для чого використовується змінна isPending?**

Вона показує, що надсилання форми ще виконується. За її допомогою можна змінити текст кнопки на «Надсилання...» та заблокувати повторне натискання.
